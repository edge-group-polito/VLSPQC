The source was exported from a local clone with `git archive v2.0.0` (the clone's
HEAD is past the tag and was not used). Each variant folder holds a copy of the
upstream `mlkem/` directory (single compilation unit: `mlkem_native.c`, which
includes `src/*.c`) and a small `include/` directory of compatibility headers.

## Removed from the upstream tree
- `mlkem/src/native/` (AArch64, x86_64, RISC-V, PPC64LE backends), `mlkem/src/fips202/native/` (AArch64, ARMv8.1-M, x86_64
  FIPS 202 backends) and `mlkem_native_asm.S`: only the portable C backend exists in this tree; no
  `MLK_CONFIG_USE_NATIVE_BACKEND_*` option is defined. (`mlkem_native.c` still names the removed files inside
  `#if defined(MLK_CONFIG_USE_NATIVE_BACKEND_*)` blocks that are never compiled.)
- `mlkem/README.md`, `proofs/`, `test/`, `examples/`, CI and build-system files.

## Local changes
1. `mlkem/mlkem_native_config.h` (per variant, two lines):
   - `MLK_CONFIG_PARAMETER_SET` set to 512 / 768 / 1024;
   - `MLK_CONFIG_NO_RANDOMIZED_API` enabled. The KAT harness only uses the
     deterministic API (`keypair_derand`, `enc_derand`, `dec`), so no
     `randombytes()` provider is needed; all randomness comes from the harness
     NIST DRBG (`harness/gen/rng.c`).
2. `include/{kem.h,api.h,params.h}` (new, not upstream): map the harness names
   `crypto_kem_*` / `KYBER_*` / `CRYPTO_*` onto the `PQCP_MLKEM_NATIVE_MLKEM<level>_*`
   API and `MLKEM<level>_*` size constants of `mlkem_native.h`.

No other upstream file was modified (checked with `diff -r` against the pristine export).

## Verification
- Upstream's own `test/src/gen_KAT.c` (with its `notrandombytes` RNG), built with plain
  `gcc` against these trees, reproduces the `kat-sha256` values of upstream `META.yml`
  for all three parameter sets.
- Every record of the `.rsp` files generated by this repository's harness was replayed
  through the pristine upstream build (keypair/enc coins in, pk/sk/ct/ss compared): 100/100
  records, 0 mismatches, for each of the three variants.

## Notes
- Pre-FIPS Kyber round-3 code that used to live here is preserved in git history at the
  `pre-fips-migration` tag. Its KATs are not compatible with these.

The source was exported from a local clone with `git archive v2.0.0` (the clone's
HEAD is past the tag and was not used). Each variant folder holds a copy of the
upstream `mldsa/` directory (single compilation unit: `mldsa_native.c`, which
includes `src/*.c`) and a small `include/` directory of compatibility headers.

The old variant names `ML-DSA-2/3/5` (Dilithium 2/3/5) are kept as deprecated `make`
aliases for `ML-DSA-44/65/87`; their KATs are not compatible.

## Removed from the upstream tree
- `mldsa/src/native/` (AArch64, x86_64, RISC-V backends), `mldsa/src/fips202/native/` (FIPS 202 backends) and
  `mldsa_native_asm.S`: only the portable C backend exists in this tree; no `MLD_CONFIG_USE_NATIVE_BACKEND_*` option is
  defined. (`mldsa_native.c` still names the removed files inside `#if` blocks that are never compiled.)
- `mldsa/README.md`, `proofs/`, `test/`, `examples/`, CI and build-system files.

## Local changes
1. `mldsa/mldsa_native_config.h` (per variant, two lines):
   - `MLD_CONFIG_PARAMETER_SET` set to 44 / 65 / 87;
   - `MLD_CONFIG_NO_RANDOMIZED_API` enabled. The harness supplies the key-generation seed
     and the signing randomness explicitly (`keypair_internal`, `signature_internal`), so no
     `randombytes()` provider is needed; all randomness comes from the harness NIST DRBG
     (`harness/gen/rng.c`).
2. `include/{api.h,params.h,sign.h}` (new, not upstream): map the harness calls
   `crypto_sign_keypair(pk, sk, seed)`, `crypto_sign(sm, &smlen, m, mlen, ctx, ctxlen, sk, rnd)` and
   `crypto_sign_open(...)` onto `keypair_internal`, `prepare_domain_separation_prefix` +
   `signature_internal` (FIPS 204 Algorithm 2 with `ctx`, `MLD_PREHASH_NONE`) and `verify`.
   The signed-message layout is `sm = sig || m`.

No other upstream file was modified (checked with `diff -r` against the pristine export).

## Verification
- Upstream's own `test/src/gen_KAT.c` (with its `notrandombytes` RNG), built with plain `gcc`
  against these trees, reproduces the `kat-sha256` values of upstream `META.yml` for all three
  parameter sets.
- Every record of the `.rsp` files generated by this repository's harness was replayed through
  the pristine upstream build (`keypair_internal`, `prepare_domain_separation_prefix` +
  `signature_internal`, `verify`; sk/pk/sig compared byte for byte): 100/100 records, 0 mismatches,
  for each of the three variants.

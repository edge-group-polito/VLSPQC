The source was exported from the local clone `/home/aledolme/home/SLIDER/slhdsa-c` with
`git archive 174c02e…` (the clone is the one used by the SLIDER SLH-DSA co-design project; its
`sw-new/slh-dsa/slhdsa-c/*.{c,h}` are byte-identical to the files imported here).

`slhdsa-c/` holds the upstream `*.c` / `*.h` files verbatim and is shared by all variants: the
parameter set is selected at run time through the `slh_param_t` object (`slh_dsa_sha2_128s`, …).
Each `SLH-DSA-<hash>-<level><s|f>/include/` holds a small compatibility layer.

## Removed from the upstream tree
`.clang-format`, `CODEOWNERS`, `Makefile`, `README.md`, `flake.*`, `nix/`, `proofs/` (CBMC),
`integration/` (liboqs), `test/` (ACVP client, experimental-parameter smoke test). Only the portable C
library sources are kept; no architecture-specific code exists in this tree (`plat_local.h` only
detects word size) and `SLH_EXPERIMENTAL` is not defined.

## Local changes
None to the upstream files. New, not upstream: `<variant>/include/{api.h,params.h}` map the harness
calls onto the library:
- `crypto_sign_keypair(pk, sk, keypair_rnd)` → `slh_keygen_internal(sk, pk, SK.seed, SK.prf, PK.seed)`
  with the three `n`-byte parts of the 3n-byte `keypair_rnd`;
- `crypto_sign(sm, &smlen, m, mlen, sk, sig_rnd)` → `slh_sign(sig, m, mlen, NULL, 0, sk, sig_rnd)`
  (pure SLH-DSA, empty context, hedged with `sig_rnd`); layout `sm = sig || m`;
- `crypto_sign_open(...)` → `slh_verify(m, mlen, sig, siglen, NULL, 0, pk)`.

## Verification
- NIST ACVP-Server vectors (`usnistgov/ACVP-Server` tag `v1.1.0.40`, `SLH-DSA-keyGen-FIPS205` and
  `SLH-DSA-sigGen-FIPS205`) replayed through the pristine upstream sources: all 12 parameter sets,
  120 key-generation cases and 36 deterministic external/pure signing cases (the 3 shortest messages
  of each set, with their context strings), each signature also verified: 0 mismatches.
- Every record of the `.rsp` files generated by this repository's harness (10 records per variant in the
  scratch cross-check) was replayed through the pristine upstream API (keygen from `keypair_rnd`, signature
  from `sig_rnd`, pk/sk/sm compared byte for byte, then verified): 0 mismatches for all 12 variants.

## Notes
- The pre-FIPS SPHINCS+ SHA2/SHAKE round-3 trees (and the earlier partial `s`-size FIPS 205 wrappers)
  that used to live in `algorithms/signatures/standard/SLH-DSA` and `algorithms/signatures/standard/SLH-DSA-SHA2` are preserved in git history at
  the `pre-fips-migration` tag. The `robust` mode is not part of FIPS 205 and is no longer provided.
- `algorithms/legacy/SLH-DSA-Haraka` and `algorithms/legacy/SLH-DSA-Haraka-AES` (SPHINCS+ with Haraka) are NOT part
  of FIPS 205; they stay in place as legacy code, outside `test-all`.
- HashSLH-DSA (`slh_prehash.c`) is compiled but not exercised by the KAT harness.
